Getting started

Core UI ships as a standalone Angular library. Build it once, load the shared theme, and start composing screens with tokens instead of hard-coded colors.

Installation

The library lives in the same workspace as this documentation app, so the demo consumes the source directly. For a separate application, build the library and install the output as a local package.

⚠ Peer versions. Core UI targets Angular 18 and has no runtime dependencies beyond {{ '@angular/core' }} and {{ '@angular/common' }}.

Global theme

theme.css defines the light palette, the dark palette and the data-theme hooks that switch between them. Load it exactly once — the documentation app adds it through the styles array in angular.json.

The sheet also follows prefers-color-scheme until you set an explicit data-theme on <html>, so apps get dark mode for free.

Use a component

Every component is standalone. Import only what a template renders — the bundler drops the rest.

Design tokens

Color is expressed with CSS custom properties. Override a token globally to rebrand the whole library, or scope it to a section to theme just that area.

💡 Pair every background override with its --pl-color-on-* foreground token so contrast stays accessible in both themes.

Dark mode

Toggle the data-theme attribute — no component API changes. The demo persists the choice in localStorage through a small ThemeService; copy that pattern or wire it to your own store.

Adding components

Documentation is registry-driven. Navigation, the landing-page index, page titles and previous/next links all read from component-registry.ts, and each docs page is lazy-loaded from the route map.

To document a new component: add a registry entry, create a page that reuses <docs-demo-card>, <docs-prop-table> and <docs-toc>, then register its lazy import.
